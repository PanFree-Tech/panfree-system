## #1 — middleware.js verifica clientes.role (ADR-002)

**Severidad:** Media
**Archivo:** `src/middleware.js`
**PR:** #63

### Problema

El middleware leía `user.app_metadata.role`, pero el rol real vive en `clientes.role`. Si un admin era degradado en `clientes.role`, el middleware seguía dejándolo pasar hasta que se re-logueara (porque el JWT viejo seguía teniendo `role: 'admin'` en `app_metadata`).

### Solución

- Consultar `clientes.role` con `service_role` (bypass RLS).
- Usar `clientes.role` como fuente de verdad.
- Fallback a `app_metadata.role` si `service_role` no está configurado o la query falla.
- Fail-closed: si no es admin, redirige a `/unauthorized` (o 403 en API).

### Verificación

- `npm test`: 75/75.
- `npm run build`: OK (middleware 86 kB).
- Test manual: admin accede a `/admin` (OK).

## #2 — Documentar ga-metrics (500 desde consola)

**Severidad:** Media
**Archivo:** `src/app/api/admin/ga-metrics/route.js`
**PR:** #62

### Problema

El endpoint devolvía 500 cuando se llamaba desde la consola del navegador sin el header `Authorization`. Pero funcionaba desde el admin panel (que sí manda el JWT).

### Solución

No es un bug real (es el fail-closed de `requireAuth`). Se documentó en `docs/audits/fase-4-deuda-pendiente.md` que el endpoint solo se llama desde el admin panel, no desde consola.

### Verificación

- `/api/admin/ga-metrics` devuelve 200 desde el admin panel.
- Devuelve 401 desde consola (fail-closed, correcto).

**Severidad:** Baja
**Archivos:** `src/app/perfil/page.js`, `src/app/perfil/puntos/page.js`

## #5 — Error cargando productos en build estático

**Severidad:** Baja
**Archivos:** `src/app/page.js`, `src/app/catalogo/page.js`
**PR:** #64

### Problema

Durante `npm run build`, Next.js intentaba hacer fetch a Supabase en `cargarDatos()` (Server Component), pero como no hay servidor corriendo, devolvía 404 → HTML. El `logger.error('Error cargando productos')` ensuciaba el output del build.

### Solución

Agregado `export const dynamic = 'force-dynamic'` en `src/app/page.js` y `src/app/catalogo/page.js`. Las páginas se renderizan en cada request (con cookies del usuario), no en el build (sin conexión a Supabase).

### Verificación

- `npm run build`: OK (51/51 static pages, sin `Error cargando productos`).
- La home y el catálogo siguen funcionando en producción.
